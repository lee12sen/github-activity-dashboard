# PRD — GitHub 학습 활동 대시보드

## 1. 개요

GitHub API로 개인 저장소의 커밋·이슈·PR·로드맵 데이터를 수집해, 프로젝트가 잘 유지보수되고 있는지 스스로 점검할 수 있는 개인용 웹 대시보드.

## 2. 문제 정의 / 핵심 가치

OSS기반 SW프로그래밍 수업에서 GitHub 활동 자체가 학습·평가의 중심이 되는데, 정작 "방치된 이슈는 없는지", "최근에도 꾸준히 작업하고 있는지", "계획한 만큼 진행됐는지"를 한눈에 돌아볼 방법이 없었다.

**핵심 가치**: 내 프로젝트가 좋은 품질로 유지보수되고 있는가를 스스로 확인하는 대시보드.

## 3. 타겟 사용자

개인 개발자(본인) — 사이드 프로젝트나 과제를 진행하면서, 자신의 프로젝트가 잘 관리되고 있는지 스스로 점검하고 싶은 사람. 팀 단위 협업 도구가 아니라 1인 개발자를 위한 자기 점검용 도구.

## 4. 사용자 시나리오

> 저녁에 작업을 시작하기 전, 대시보드에 접속한다. "커밋 빈도" 카드를 보고 최근 며칠간 작업이 뜸했다는 걸 확인한다. "이슈/PR 처리 현황" 카드에서 오래 방치된 이슈가 있는 걸 발견하고 먼저 처리하기로 한다. "로드맵 진행률" 카드를 보고 계획 대비 얼마나 진행됐는지 확인한 뒤, 오늘 작업할 범위를 정한다.

## 5. 기능 요구사항 (Functional Requirements)

### FR-1. 이슈/PR 처리 현황
- 저장소의 열린/닫힌 이슈 개수를 가져와 표시한다.
- 열린/닫힌 PR 개수를 가져와 표시한다.
- 최근 N주간 처리(닫힌)된 이슈 수 추이를 번다운 형태로 표시한다.
- 오래 방치된(예: 14일 이상 업데이트 없는) 이슈/PR을 구분해서 보여준다.

### FR-2. 커밋 빈도 그래프
- 최근 8주간 주 단위 커밋 수를 집계해 막대그래프로 표시한다.
- 이번 주 커밋 수와 지난주 대비 증감을 함께 표시한다.

### FR-3. 로드맵/마일스톤 진행률
- 프로젝트 로드맵(`docs/ROADMAP.md`)의 체크리스트 항목 중 완료된 비율을 계산한다.
- 진행률을 퍼센트 진행 바로 표시한다.
- (구현 세부사항: 체크리스트를 로드맵 파일에서 직접 파싱할지, 별도 데이터로 관리할지는 1단계 구현 시 확정)

## 6. 화면 요구사항 (Screen Requirements)

- 헤더: 프로젝트명 + 연결된 GitHub 계정 정보
- 카드 3개를 한 화면에 배치 (반응형 그리드 — 데스크톱 3열, 모바일 1열)
  - 카드 1: 이슈/PR 처리 현황
  - 카드 2: 커밋 빈도 그래프
  - 카드 3: 로드맵 진행률
- 별도 라우팅 없이 한 페이지로 구성
- 로그인/설정 화면은 v1 범위 밖 (저장소는 코드에 고정값으로 지정)

## 7. 데이터 소스

GitHub REST API. 별도 데이터베이스 없이 API 응답을 그대로 가공해서 사용한다.

## 8. v1 범위 밖 — 향후 확장 후보

- **v2 (기존 GitHub 데이터만으로 계산 가능)**: Cycle Time(이슈 시작→완료), Lead Time for Changes(첫 커밋→머지)
- **v3+ (선행 인프라 필요)**: Deployment Frequency(릴리즈 태그 필요), MTTR(버그 라벨링 체계 필요)
- **보류**: 팀 단위 협업 대시보드(스프린트 진행률, 팀원별 활동 등) — 개인용으로 범위를 좁히며 제외
- **기각**: 이슈/커밋/마일스톤 템플릿 삽입 기능 — GitHub 네이티브 기능(`.github/ISSUE_TEMPLATE/`, `pull_request_template.md`, `git config commit.template`)으로 이미 해결 가능해 커스텀 기능으로 만들지 않음
